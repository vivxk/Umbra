# Umbra

**Minimal Privacy-First, Fail-Closed Linux Network Boundary**

Umbra is a lightweight Linux utility written in safe Rust that enforces transparent Tor routing, DNS leak prevention, total IPv6 blocking, and MAC address randomization. Designed as a clean-room privacy boundary, Umbra operates under a strict **fail-closed** security model: if Tor or any system dependency fails, network egress is immediately blocked rather than falling back to direct clearnet internet.

## Core Principles

- **Fail-Closed by Design**: Application traffic is never allowed to reach the physical network directly. If Tor crashes, hangs, or terminates, network traffic is dropped at the kernel level.
- **Kernel-Enforced Security**: All routing policies reside in Linux `nftables` (`table inet umbra`). Process termination, crashes, or signals cannot disrupt active protection.
- **Small & Auditable**: Clean-room implementation in safe Rust with minimal external dependencies.
- **Minimal Persistent Footprint**: Runtime session state is stored ephemerally in `/run/umbra/` (tmpfs) and is cleared on reboot; no long-lived configuration databases or background daemons.
- **Ownership Verification**: All firewall rules, tables, chains, and Tor configuration fragments are cryptographically and textually tagged (`umbra-managed`). Foreign firewall tables, host DNS configurations, and unrelated network rules remain completely untouched.
- **Zero Telemetry**: No outbound diagnostic requests, public IP query pings, or telemetry.

## Architecture & Security Invariants

### Traffic Flow

```text
Application Traffic (TCP, UDP, DNS)
             │
             ▼
   [ nftables: table inet umbra ]
             │
   ┌─────────┴───────────────────────────────────────────────────────┐
   │                                                                 │
   ▼ (TCP non-Tor)               ▼ (UDP 53 / Loopback 127.0.0.53:53) ▼ (All Other Traffic)
Tor TransPort (127.0.0.1:9040)  Tor DNSPort (127.0.0.1:5353)         BLOCKED / DROPPED
   │                             │                                   - Direct IPv4 egress: DROP
   └──────────────┬──────────────┘                                   - IPv6 (ip6 daddr != ::1): DROP
                  ▼                                                  - TCP 53: REJECT with TCP RST
          Tor Onion Router                                           - QUIC (UDP 443): DROP
         (Unprivileged UID)                                          - DoT (TCP/UDP 853): DROP
                  │                                                  - Arbitrary UDP: DROP
                  ▼ (Encrypted Egress)
             Internet
```

### Security Invariants

| Boundary Layer | Policy / Enforcement | Security Invariant |
| :--- | :--- | :--- |
| **Fail-Closed Guarantee** | Kernel `output_filter` default policy `drop` | If Tor stops or fails, egress traffic is dropped; no fallback to direct clearnet. |
| **Tor Transparent Routing** | `output_nat` redirect to `127.0.0.1:9040` | All outbound TCP application traffic is transparently routed via Tor TransPort. |
| **Tor Process Exemption** | `skuid <tor_uid> return / accept` | Outbound traffic generated by the Tor process is exempted from redirection loops. |
| **DNS Leak Prevention** | Intercept UDP 53 -> `127.0.0.1:5353` | Clearnet UDP DNS and loopback stub resolvers (`127.0.0.53`, `127.0.0.1`) are intercepted. |
| **TCP DNS Bypass Prevention**| `tcp dport 53 reject with tcp reset` | Direct TCP DNS queries are rejected immediately with RST and never forwarded to TransPort. |
| **IPv6 Leak Prevention** | `ip6 daddr != ::1 drop` (Strategy B) | All external IPv6 egress is blocked immediately, preventing IPv6 bypass leaks. |
| **QUIC / HTTP/3 Drop** | `udp dport 443 drop` | Blocks QUIC protocol traffic which cannot be routed through Tor TransPort. |
| **DoT / DoQ Drop** | `tcp dport 853 drop`, `udp dport 853 drop` | Prevents DNS-over-TLS and DNS-over-QUIC from bypassing Tor DNSPort. |
| **MAC Address Privacy** | RFC-compliant locally administered unicast | Randomizes egress MAC address on start; safely restores original baseline on stop/recovery. |
| **Firewall Ownership** | Marker `# umbra-managed` on all objects | Prevents mutation or deletion of foreign firewall tables, chains, or rulesets. |

## Prerequisites

- **Operating System**: Linux kernel 5.4 or newer.
- **Firewall**: `nftables` (`nft` v1.0 or newer).
- **Tor**: `tor` daemon (v0.4.x or newer) running under an unprivileged user (e.g. `debian-tor` or `tor`).
- **Network Tools**: `iproute2` (`ip` command), `sysfs`.
- **Compiler**: Rust toolchain (edition 2021, rustc 1.80+) to build from source.

## Installation

### 1. Build and Install via Makefile

```bash
# Clone the repository
git clone https://github.com/umbra/umbra.git
cd umbra

# Build release binary and install to system
sudo make install
```

The installer performs the following actions:
1. Compiles the optimized release binary (`cargo build --release`).
2. Installs the executable to `/usr/bin/umbra` with permissions `0755` (and symlinks `/usr/local/bin/umbra`).
3. Installs the Tor configuration fragment to `/etc/tor/torrc.d/umbra.conf` (authenticated with `# umbra-managed`).
4. Installs the systemd unit template to `/etc/systemd/system/umbra-boot.service`.

### 2. Verify Tor Configuration

Ensure your `/etc/tor/torrc` includes configuration fragments:
```text
%include /etc/tor/torrc.d/*.conf
```
Restart Tor if necessary:
```bash
sudo systemctl restart tor
```

## CLI Usage

Umbra provides an intentionally minimal CLI:

```bash
# 1. Start fail-closed privacy routing
sudo umbra start

# Optional: Override egress interface explicitly
sudo umbra start --interface eth0

# 2. Inspect live system status and verification checks
sudo umbra status

# 3. Request a fresh Tor identity circuit (NEWNYM)
sudo umbra newnym

# 4. Stop privacy routing and restore original MAC and networking state
sudo umbra stop

# 5. Recover normal networking after a power outage or unexpected crash
sudo umbra recover --normal

# Force recovery if session state is missing or corrupted
sudo umbra recover --force

# 6. Display version
umbra version
```

### Understanding `umbra status`

`umbra status` queries the live kernel and Tor subsystems to report authoritative state:
- `ACTIVE`: Umbra firewall table is present, rules verified, Tor running and listening, MAC randomized.
- `INACTIVE`: Normal networking active, no Umbra firewall table present, baseline MAC restored.
- `RECOVERY_REQUIRED`: Firewall table exists or state recorded, but live verification failed (e.g., Tor stopped unexpectedly). The system remains safely fail-closed until `recover` or `stop` is run.

## Systemd Boot-Enforced Mode

For systems requiring boot-time fail-closed protection, Umbra provides `umbra-boot.service`:

```bash
# Enable Umbra to start before network-online.target on boot
sudo systemctl enable umbra-boot.service

# Start the boot service immediately
sudo systemctl start umbra-boot.service

# Check service status
sudo systemctl status umbra-boot.service
```

`umbra-boot.service` is a `oneshot` unit (`RemainAfterExit=yes`) ensuring that no background daemon is kept running. The Linux kernel nftables ruleset maintains all enforcement. In accordance with Umbra security invariants, failure of the boot unit never defaults to an open network.

## Uninstallation

Per Section 89 of the Umbra specification, uninstallation strictly enforces an **inactive check**: it refuses to remove binaries if Umbra is currently active or in an unrecovered state. This prevents orphaned firewall rules or randomized MAC settings from disabling host networking.

```bash
# Verify Umbra is stopped first
sudo umbra stop

# Run uninstaller
sudo make uninstall
# or:
sudo bash scripts/uninstall.sh
```

The uninstaller:
1. Verifies that Umbra is completely `INACTIVE` (refuses removal otherwise).
2. Disables and removes `umbra-boot.service` from systemd.
3. Verifies ownership and safely removes `/etc/tor/torrc.d/umbra.conf`.
4. Removes `/usr/bin/umbra` and `/usr/local/bin/umbra`.
5. Cleans `/run/umbra/`.

## Testing & Leak Prevention Audit

Umbra includes a comprehensive automated test suite. Privileged network tests execute inside isolated Linux network namespaces (`ip netns` / `unshare -r -n`) to guarantee that the development host's firewall and networking are never modified.

### Run All Tests

```bash
cargo test
```

### Run Static Analysis and Linter Checks

```bash
make lint
# equivalent to:
cargo clippy --all-targets --all-features -- -D warnings
cargo fmt --check
```

### Run End-to-End Leak Prevention Test Suite

```bash
cargo test --test leak_prevention_namespace -- --nocapture
```

The End-to-End Leak Prevention Suite verifies:
1. **Direct IPv4 Egress**: All non-Tor TCP is transparently redirected to Tor TransPort; non-Tor UDP is dropped fail-closed (`EPERM`).
2. **Direct IPv6 Egress**: External IPv6 TCP, UDP, and DNS are immediately dropped at the kernel filter (`EPERM`).
3. **Clearnet DNS Redirection**: Outbound UDP DNS (port 53) to public resolvers (e.g. `8.8.8.8`) is transparently redirected to Tor DNSPort.
4. **TCP DNS Rejection**: TCP DNS queries (port 53) are rejected with TCP RST and never leaked to TransPort.
5. **Loopback Stub DNS Interception**: Queries to `127.0.0.53:53` (systemd-resolved) and `127.0.0.1:53` are intercepted and routed to Tor DNSPort.
6. **QUIC Bypass Drop**: UDP port 443 packets are dropped immediately (`EPERM`).
7. **DoT / DoQ Bypass Drop**: TCP port 853 and UDP port 853 packets are dropped immediately.
8. **Tor Failure Injection**: Simulates Tor daemon crash (`SIGKILL`); verifies the system remains strictly fail-closed (`ECONNREFUSED` / packet drops) and never leaks to clearnet.

## Security Guardrails

As documented in `AGENTS.md`, Umbra development enforces strict operational boundaries:
- **Never flush the host firewall**: `nft flush ruleset`, `iptables -F`, or `ip6tables -F` are never executed on the host.
- **Never modify unrelated tables**: Existing host tables (Docker, UFW, firewalld, WireGuard) are isolated and preserved.
- **Privilege Separation**: Tor must always run as an unprivileged user, never as `root`.
- **Fail-Closed Guarantee**: Under no circumstances will Umbra open the network to direct clearnet when an error occurs.
